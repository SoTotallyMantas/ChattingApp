Priklausomybės nuo kitų programinių produktų:
•	PostgreSQL - duomenų bazė;
•	Docker - konteinerizavimo programa;
•	Janus - medijos srautų valdymo serveris;
•	GarageHQ - objektų saugyklą.
Kompiuterinės technikos parametrai:
kuriant programinę realizaciją ir testuojant sistemą buvo naudotas stacionarus kompiuteris su „Ryzen 5 7600X“ 6 brandolių procesoriumi, 32 GB RAM atminties ir „Radeon RX 9700 XT“ vaizdo plokšte.
Diegimo aprašas:
kad įdiegti programinę realizacija, reikia atsisiųsti Docker programą ir projekto šaltinio kodą, atidaryti projekto katalogą ir užpildyti tipinę konfigūraciją.
Tipinė konfigūracija:
tipinė konfigūracija sudaryta iš .env.example, garage.toml.example, janus.jcfg.example, nginx-app.conf.example, docker-compose.yml failų. Pagrindinis konfigūracijos failas yra .env.example, kuriame laikomi visi sisteminiai kintamieji, skirti šifravimui ir serverio dalies prisijungimui prie kitų konteinerizuotų paslaugų. Kintamieji užpildomi .env.example faile ir docker-compose.yml faile nustatomi konteinerių tinklo prievadai.
Failas .env.example yra šablonas, kuris turi būti sukonfigūruotas prieš paleidžiant sistemą, pirmiausia pervadinti .env.example į .env. Tuomet įrašyti .env kintamuosius: POSTGRES_USER: duomenų bazės naudotojo vardas; POSTGRES_PASSWORD: duomenų bazės slaptažodis; POSTGRES_DB: duomenų bazės pavadinimas; PGADMIN_DEFAULT_EMAIL: duomenų bazės naudotojo sąsajos el. pašto prisijungimas; PGADMIN_DEFAULT_PASSWORD: duomenų bazės naudotojo sąsajos slaptažodis; JWT_SECRET: atsitiktinis raktas, naudojamas autentifikacijos žetonų kūrimui; DATA_ENCRYPTION_MASTER_KEY: 32 baitų base64 raktas, naudojamas duomenų šifravimui. Taip pat, kad paruošti objektų saugyklos kintamuosius, reikia iš pirmo atlikti konfigūracija per Garage Web UI, kurioje sukonfigūruojamas klasteris (angl. Cluster), sukuriamas kibiras (angl. Bucket) ir S3 prieigos raktai, reikalingi serverio daliai pasiekti saugyklą. Kad tai atlikti, reikia įjungti objektų saugyklą ir naudotojo sąsają paleidus komandą: docker compose up -d garage garage-webui. Kai abi paslaugos sėkmingai pasileidžia, naršyklėje atidaroma Garage Web UI pagal docker-compose.yml Garage Web UI konteinerio nustatytą prievadą. Prisijungus pateikiamas administravimo valdymo skydelis. Klasterio skiltyje paspaudžiamas mygtukas prisijungti (angl. Connect), kuriame pateikiama komanda docker exec garage /garage node id; ji paleidžiama terminale ir gauta išvestis įvėdamą į prisijungimo lauką. Toliau perėjus prie rakto skilties pasirenkama sukurti raktą (angl. Create Key), įvedamas rakto pavadinimas „backend-access“ ir patvirtinama (angl. Submit). Tuomet matomas rakto įrašas, kuriame nurodomas rakto pavadinimas, rakto identifikatorius ir slaptas raktas, kuriuos atitinkamai reikia užpildyti į .env kintamuosius: S3_KEY_NAME: rakto pavadinimas; S3_KEY_ID: rakto identifikatorius; S3_KEY_SECRET: slaptas raktas. Sukūrus raktą ir užpildžius konfigūracijos kintamuosius, pereinama į kibiro skiltį, kur paspaudus mygtuką sukurti kibirą (angl. Create Bucket), įrašomas kibiro pavadinimas ir patvirtinama. Atsiradus kibirui ir paspaudus valdyti (angl. Manage), atidaromas valdymo skydelis, kuriame spaudžiama teisės (angl. Permissions), kur pasirenkamas leisti raktą (angl. Allow Key), nurodomas „backend-access“ raktas ir teisės: skaityti (angl. Read); rašyti (angl. Write) ir savininkas (angl. Owner), tuomet patvirtinamas. Užbaigus konfigūraciją į .env įrašomas S3_BUCKET: sukurto kibiro pavadinimas. 
Programinės realizacijos paleidimas:
norint paleisti programinę realizaciją, reikia įvykdyti diegimo žingsnius ir panaudoti projekto kataloge komandą docker compose up -d -build, kuri atsiųs ir sudiegs programas į konteinerius ir visas reikalingas priklausomybes.
Sėkmingai įvykdžius komandą iš pagrindinio kompiuterio, kuriame įvykdyta komanda, galima pasiekti svetainę naudojant lokalų adresą.
Programinės realizacijos šalinimo žingsniai: 
norint pašalinti programinę realizaciją, programinės realizacijos kataloge reikia panaudoti docker compose down -v ir panaikinti projekto katalogą.
